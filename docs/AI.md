# AI: Impact Engine, RAG, and Copilot

Three AI surfaces share one principle: the model narrates and reasons over
evidence the platform already computed. It never invents facts and never decides
what is stored. If the model is unavailable, the platform still works.

## 1. Impact engine

When the change engine records a `DetectedChange`, `app/intelligence/engine.py`
turns it into an `Insight` answering the SOP's eight questions:

| Field | Source |
| --- | --- |
| What changed? | Diff of `before` / `after` over `field_changes` |
| Why does it matter? | Module rules + LLM narrative |
| Which company is affected? | Resolved sponsor(s) on the entity |
| What products are impacted? | Resolved drug(s) and linked patents |
| Potential generic opportunity? | Derived from exclusivity posture and challenger count |
| Exclusivity risk? | PTE presence, expiry proximity, Orange Book exclusivity codes |
| Recommended action? | Module playbook + priority band |
| Priority level? | `compute_priority` → Critical / High / Medium / Low |

The deterministic parts (affected entities, priority score) are computed from
data. The narrative fields are generated by the LLM *grounded in those computed
facts*, then stored alongside `evidence` so the UI can show what the model saw.
`generated_by` records whether a row came from the LLM or the fallback path.

Baseline changes — the first snapshot of a source — are marked processed without
generating insights, so onboarding a new source does not spam the dashboard.

## 2. Retriever (RAG)

`app/copilot/rag.py` builds and queries the retrieval corpus.

- **Corpus building** (`app/search/index.py`): every meaningful record is
  flattened into a text chunk — a drug's regulatory profile, a patent's
  attributes, an insight narrative, an Orange Book edition summary — and stored
  in `document_chunks` with a `module`, `entity_key`, and metadata.
- **Embeddings** (`app/copilot/embeddings.py`): a provider abstraction. Azure
  OpenAI embeddings in production; a deterministic local hashing embedder for
  offline use so tests and local runs need no key.
- **Storage**: the vector is written to a pgvector column and mirrored to JSON
  so the SQLite/NumPy backend can serve the same rows.
- **Retrieval**: cosine similarity search, filtered by `module` / entity type,
  returning citations (`source_type`, `source_id`, `title`) that the copilot
  shows to the user.

## 3. Copilot

`app/copilot/agent.py` runs a tool-using loop. The model plans, calls the same
APIs a human would, and composes an answer with citations.

```
Question
   │
   ▼
Retrieve relevant chunks (RAG)  ──▶  candidate evidence
   │
   ▼
Plan: which tools answer this?
   │
   ├─▶ structured query tool  (SQL over the fact tables via repositories)
   ├─▶ entity lookup tool     (drug / patent / sponsor 360)
   ├─▶ analytics tool         (trends, distributions)
   └─▶ knowledge-graph tool   (relationship traversal)
   │
   ▼
Synthesize answer + cite sources
   │
   ▼
Persist to copilot_conversations / copilot_messages
```

Example questions the copilot is wired to answer (also served by
`GET /api/v1/copilot/suggested-questions`):

- "Show all new PTE applications this month."
- "Compare the latest Orange Book supplement with the previous edition."
- "Show active moieties approved in oncology."
- "Show Paragraph IV filings for diabetes products."
- "List patents expiring in the next 24 months."
- "Which sponsors received PTE approvals recently?"
- "Find generic opportunities for 2028."

Time-sensitive questions route to the structured tool (deterministic filters on
`filing_date`, `granted_date`, `expiration_date`), not the LLM's memory. The
copilot's job is to pick the filters, not to know the dates.

## Guardrails

- **Grounding** — the answer must cite at least one retrieved or queried record;
  uncited claims are dropped.
- **No write path** — the copilot has read-only tools. Mutations happen only
  through the authenticated API, with audit logging.
- **Least privilege** — the copilot runs with the caller's scopes; a viewer can
  ask questions but the tools it may call are capped accordingly.
- **Cost and latency** — token usage and `latency_ms` are stored per message for
  monitoring.
- **Deterministic fallback** — with no LLM key, the copilot returns the
  retrieval-and-compute result without a narrative, rather than failing.

## MCP server

`app/mcp/` exposes the same read tools over the Model Context Protocol, so
external agents (or the OpenHands agent) can query the platform without going
through the dashboard. The MCP surface is scoped the same way as the REST API.
